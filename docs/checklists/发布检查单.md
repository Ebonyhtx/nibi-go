## 0. 待决策项

### 0.1 分发方式（三选一）

| 方案 | 做法 | 代价 |
|---|---|---|
| **公开发布仓（推荐起步）** | 新建公开仓（如 `nibi-go-releases`）只放 Release 产物（APK + checksums）；源码仓保持私有；App 检查器指向该仓 | 发布仓匿名可读（产物公开）；需一个发布脚本 push 产物 |
| R2/自建分发 | 产物上传 R2/CDN；检查器换成自定义 manifest（version/sha256/url） | 需要分发端维护；离线安装包可手动提供 |
| 暂不自动更新 | 只做手动下载安装；更新检查器保留但关闭入口 | 用户需手动跟新版本 |

> 当前实现按 GitHub Releases 协议（`updater-core.ts` 可解析任意 GitHub release；`RELEASE_REPO` 环境变量可切换仓）。

### 0.2 签名 keystore

- 位置建议：**本机 `~/.nibi/keystore/nibi-go-release.jks`**（不在仓库内、不在 App 目录内）
- 密码：owner 保管（密码管理器）；**不写入任何配置文件、不进对话**
- 生成（owner 本机执行，密码自行输入）：
  ```bash
  keytool -genkeypair -v -keystore ~/.nibi/keystore/nibi-go-release.jks \
    -alias nibi-go -keyalg RSA -keysize 4096 -validity 10000 \
    -dname "CN=NIBI-GO, O=NIBI Studio, C=CN"
  ```
- Gradle 注入方式（二选一，均不落盘密码）：
  1. `android/gradle.properties` 只放路径 + 环境变量放密码（`NIBI_KEYSTORE_PASS`/`NIBI_KEY_PASS`）；
  2. 本地 `~/.gradle/gradle.properties` 存路径（密码仍走环境变量）。
- **签名链三链**（plan.md A4）：debug（自动）/ release（上述 keystore）/ 更新覆盖安装必须同签名——一旦发布，keystore 不可更换。

## 1. 版本发布流程（每次）

```bash
# 1) 版本号（三处一致：app/app.json version + android versionName 由 prebuild 生成 + CHANGELOG）
node -e "const fs=require('fs');const p='app/app.json';const d=JSON.parse(fs.readFileSync(p));d.expo.version='X.Y.Z';fs.writeFileSync(p,JSON.stringify(d,null,2)+'\n')"

# 2) 全量回归（必须全绿）
node scripts/check-boundaries.mjs && pnpm -r --if-present run test && pnpm -r --if-present run typecheck

# 3) release 构建（密码由 owner 输入环境变量）
cd app/android && ./gradlew assembleRelease   # 需已配置 0.2 的签名

# 4) 产物与校验
sha256sum app/build/outputs/apk/release/app-release.apk > app-release.apk.sha256

# 5) 发布（按 0.1 决策的通道）
#    GitHub 公开发布仓：gh release create vX.Y.Z app-release.apk --repo <发布仓>
```
