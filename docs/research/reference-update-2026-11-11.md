# 参考仓更新影响分析（2026-11-11）

> 对照基准：本仓 ADR-INDEX pin（dsh-Go v1.0.12 @ d5ad25c5 / nibi-client dev @ ff1c5f4f）。
> 本次更新：dsh-Go v1.0.12 → **v1.0.15**（485 commits，三天）；nibi-client dev **无新增**（ff1c5f4f 仍是最新，npm 平台包仍 4.0.1）。

## 一、dsh-Go v1.0.13–15 的重大变化

### 1. 手机操控三次大版本迭代（121 个 phone commits）——对 NIBI-GO 模块 B 工具面设计的影响

v1.0.14/15 的手机操控已远超我调研时的 1.0.12 状态，新增能力逐项评估：

| dsh-Go 新能力 | 机制 | 对 NIBI-GO 的影响 |
|---|---|---|
| **多任务并行**：每对话各自批准/暂停/停止，后台最多 3 个任务（可配） | PhoneTasks 从单任务变多槽 | **D13 工具面设计修正**：`PhoneTasks` 单例假设作废，PhoneToolsAdapter 接口需要 `taskId` 维度（confirm/tap 都要带任务归属）；悬浮条/通知只作用于显示的任务 |
| **实时后台屏预览**（只读，≤5fps，不存盘） | 特权虚拟屏 + ImageReader | GO 形态可做（随 A+C 的工具面）；增加一个 observe 流式工具 |
| **按截图坐标操作**（30s 有效，窗口切换作废，首应用许可） | 截图 → tap_xy 强化 | 对齐：tap_xy 接口已有；新增"截图有效期 + 首应用许可"语义 |
| **本机文字识别（ML Kit 中文 OCR，默认开，可关）** | Google SDK 端上推理 | GO 可选能力：读屏兜底（Canvas/游戏画面）。**注意声明**：SDK 收集机型/版本统计——NIBI-GO 若用需照此披露 |
| **任务存成技能**（脱敏：去联系人/号码/正文，预览后装成 DSH 技能） | 成功轨迹 → 技能包 | **GO 插件生态新工具类型**：phone-tools 的"轨迹→技能"导出是 GO 市场 `skills` 类目的天然来源（用户自产内容） |
| **扫码配对电脑**（相机权限新增 #22，ML Kit 按需初始化） | CameraX/MLKit | 对 NIBI-GO 扫码配对（D8）有参考：按需初始化 + 相册识码 + 粘贴链接三条路 |
| Shizuku/自 ADB shell 工具（agent 直接用 adb shell） | 特权通道新工具 | D13 工具面 13 工具清单更新 |

### 2. 运行时升级保留策略（v1.0.15）——架构级变化

**"更新引擎不再清空 Linux 环境"**：升级只替换 App 管理的部分（DSH/Node/pnpm/桥接），apt 装的工具、npm 全局包、Python/pip 包、配置、工作区全保留；不兼容/清单损坏/旧进程未停时 fail-stop 并说明原因，原环境原样保留。

对 NIBI-GO 的影响：**D13.3 运行时清单的升级语义要按这个标准设计**——模块 C 的内核/Node/shell 三件套升级必须"只替换管理面、保留用户面"（用户在插件目录装的依赖、写的技能不丢）。这验证了"依赖不逃出插件目录"的护栏（D13 供给第 2 层）方向正确，但要求升级器区分"管理面 vs 用户面"目录。

### 3. 伙伴小屋三连更（v1.0.14/15）

模型随 App 分发（作者授权已谈成）、主动邀请四档分频、完整模式自动想起记忆、导入模型 zip（第三方模型可用+AI 辅助适配）。对 D15 的影响：**素材授权模式有先例**（B 站作者授权随 App 分发）——NIBI-GO 伴侣的 Live2D 素材授权可走同款路径；"AI 辅助适配第三方模型"（只发参数名单不发模型文件）是聪明的隐私设计，值得照抄进 D15。

### 4. 新增权限：CAMERA（扫码配对）

Manifest 权限 21→22。NIBI-GO 扫码配对若用相机同样需要——权限清单（调研报告 §六.1）需补一行。

### 5. 匿名统计契约 v2

使用统计多报手机型号和厂商系统版本（不含序列号/Android ID）。若 NIBI-GO 做 usage（远期），对齐这个契约即可。

## 二、对 NIBI-GO 决策台账的修订建议（已并入 ADR-INDEX）

- **D13.4 工具面**：单任务假设 → 多任务（taskId 维度）；13 工具清单 + observe(实时屏)/learn-skill(轨迹→技能)；ML Kit OCR 列为可选能力并带披露要求。
- **D13.3 升级语义**：新增"管理面/用户面分离"原则（继承 v1.0.15 的升级保留策略）。
- **D15 伴侣**：素材授权先例（作者授权随包分发）+ AI 辅助适配（只传参数名单）。
- **D8 扫码配对**：参考 dsh-Go 的三路识码（相机/相册/粘贴链接）与 ML Kit 按需初始化。
- **能力对照表更新**：dsh-Go 又拉开的差距（多任务/实时屏/技能保存/OCR）——全部是 Android 侧能力，NIBI-GO 仍可全覆盖，但"待建成"的时间差又扩大了一截，佐证 Phase A 尽快启动的判断。

## 三、nibi-client dev：无新增

ff1c5f4f 仍是最新；npm `@nibi-studio/cli-*` 仍 4.0.1（11-07 发布）。对 D17 无影响——GO 消费的冻结产物没有新版本。

## 四、结论

本轮参考仓更新**不推翻任何既有决策**，但带来三处设计修正（工具面多任务化、运行时升级管理面/用户面分离、伴侣素材授权先例）与一份"差距扩大"的对照证据。修正已并入 ADR-INDEX 与 phone-tools 接口草案。
