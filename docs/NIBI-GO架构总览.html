NIBI-GO · 架构与决策总览

v9 · 2026-11-11 · 历史快照（当时 17 项决策定案） · 现行决策台账 D1–D19 见 docs/decisions/ADR-INDEX.md · 基于 nibi-client 全源码调研与 dsh-Go/生态对照

1决策台账（历史快照；现行 D1–D19 见 ADR-INDEX）

D1引擎
自研 Rust 内核（ZCode-rs fork 0.1.67，供应链门禁齐全）。Android 交叉编译无硬阻塞（已逐项核实）。对比 dsh-Go 的 Node+PRoot+1GB rootfs，是代际差。
D2双形态
NIBI-WORK（远控投影，复用 PWA 形式）+ NIBI-GO（本机 AGENT，UI 独立开发）。App 内切换按钮/窗口。
D3会话
两形态两份独立列表按 owner 分组，不做任何迁移（含冷交接）。会话 owner 在哪边，插件解析就在哪边。
D4WORK UI
复用现有 PWA 形式原生重画。桌面插件管理 = IPluginManagementService 手机合同（PWA 已验证）。
D5模块 C 内核
做。libnibi.so 进程内运行 + 会话库与桌面同 schema（迁移账本 0024 三方比对）。一层拓扑，无 Node Host。
D6模块 B 职责收窄
nibi-phone-bridge MCP 插件 = 仅 WORK 形态的远程路由（桌面 Agent 操控手机）。GO 形态手机操控不依赖 B。B 最后做。
D7二维码
仅路由提示（sid/mid/name），不承载加密决策，桌面 UI 零变化。
D8配对
设备级持久配对：登录 + 扫一次码；之后免扫直连，仅链接过期/凭据到期/设备删除才重配。
D9E2E 加密
做，密钥藏登录握手（账号身份协商，auth_init.meta 透传）。WORK↔桌面自动密文；PWA 永远明文；连旧桌面放行+提示未加密。服务端零改动。
D10连接拓扑
四态自动选路：本地直连 → 打洞直连（iroh）→ 中转 E2E → PWA 兜底。桌面零新增监听端口（全出站）。relay 服务端零改动。
D11跨平台留口
iOS/鸿蒙不做但选型已兼容：工具面多平台适配器接口 · C 的 FFI 平台无关 C ABI · crypto 接口化。Rust 三平台一级目标（android/apple-ios/linux-ohos）。
D12实施顺序 修正
Phase A 先行（立即启动，零内核耦合）；Phase C 挂起待两信号（主线 kernel 对齐收尾 + android 平台包发布）；B 最后。GO 形态手机操控随 A+C。3 个 spike 各约 1 天。
D13GO 插件生态 五子项
13.1 独立市场仓（npm+PR 双通道）· 13.2 Node Plugin Runtime 子进程 · 13.3 运行时点名清单 ~75-100MB · 13.4 沙箱三层 · 13.5 一层拓扑。与桌面插件体系彻底隔离。
D14桌宠 预案
状态指示器非养成游戏（继承 dsh-Go pets.md 四结论）。消费 AgentPulse 状态投影（A 阶段就定义）。挂 GO 形态。
D15伴侣 预案
轻量=内核 headless 短会话；完整=伴侣 preset 插件。状态存会话库同源 SQLite（schema 互认红利）。人设安全边界单源 @nibi/shared。挂 GO 形态。
D16付费插件层 未启动·预留
D17内核同步策略 替代分支方案
单向消费 + 票据制：GO 锁冻结的 @nibi-studio/cli-android-arm64 npm 产物（升不升级由你定）→ 缺东西开票据，你按主线节奏决定（GO 不开分支不提 PR）→ 仅紧急时分支过渡（git 依赖锁 commit）。主线永远不等 GO。
不启动收费，4 项无感预留：manifest 占位（拒绝式）/ deviceId 顺路生成（Keystore）/ JWT 复用声明 / market schema 占位。内核侧门禁主线已建成（PaidPluginGate trait + ext 执行期复核，2026-11-10）——GO 侧只需 nibi-platform 实现 license 读取+验签。

2App 架构：一个 App · 两种形态 · 两个世界

📱 NIBI-GO App
⚡ NIBI-GO 形态 🖥 NIBI-WORK 形态
⚡ NIBI-GO 形态 本机 AGENT · UI 独立开发（PWA 不是好的手机 UI）
🖐 手机操控 随 A+C · 不等 B
无障碍读屏/点按/输入 · 悬浮条三态 · 确认卡 · 应用名单（支付银行默认不碰）· 打码（Luhn/GB11643）· 后台特权通道——与 dsh-Go 同等能力，进程内桥直连内核，零网络。
🧱 一层拓扑 D13.5
App ↔ 内核直连，无 Node Host 中间层（内核合一业务+能力层）。对比桌面两层：Electron → Node Host → Rust 内核。
🤖 会话
手机内核（libnibi.so 进程内）· 离线可用 · 数据不出机 · 会话库与桌面互认。
🛡 沙箱三层 D13.4
SELinux 基线（免费）→ SandboxPolicy 强语义翻译 → 特权 mount namespace（随 B 顺路）。详见第 4 节。
🧩 插件生态（GO 专属）
nibi-go-market 独立市场仓（npm+PR 双通道、GO manifest、风险启发式扫描）· 逻辑半侧 = Node Plugin Runtime 子进程（stdio MCP）+ 声明式 HTTP 工具（无代码）· nibi-go-native-ui v1（工具卡/胶囊/状态条，RN 原生渲染，8KiB 模板预算=形状不是表现力）· 用户自开发（agent 写 → 内核 validate/install → 即用，与市场插件同能力）。
✨ 产品层（预案）
桌宠（D14）· 伴侣（D15）· 语音——全挂 GO 形态世界。
🖥 NIBI-WORK 形态 远控投影 · 复用现有 PWA 形式
🤖 会话
桌面 Host 的投影 · 桌面必须在线（runtime owner，睡眠=离线）。
🧩 插件生态（桌面投影）
桌面体系原样投影：官方市场（zcode-plugins-official）/付费插件（会员 license）/社区。插件管理 = 手机合同原生重画。与 GO 插件生态互不引用。
🖐 手机操控 模块 B 增量
dsh-Go 结构性做不到的独占能力：桌面 Agent 经 phone-bridge + Relay 操控你的手机（读屏/点按/确认卡路由回来）。
📡 连接层（四态自动选路）
🔒 用户无感 · 桌面零监听端口（全出站连接）
① 本地直连↓ ② 打洞直连（iroh）↓ ③ 中转 E2E↓ ④ PWA 明文兜底
🔑 配对与加密
登录 + 扫一次码（D7/D8）· E2E 密钥藏握手（D9）· 持久凭据免扫重连 · 连旧桌面放行并提示未加密。

3手机操控的真实结构：一份工具面 · 两个消费者

🖐 手机工具面（App 原生 Kotlin 能力） 无障碍读屏 · 点按/输入 · 悬浮条 · 确认卡 · 打码 · SafetyGate · 后台特权通道——与引擎无关

dsh-Go 的手机操控约 150 个类全部基于标准 Android API，无一依赖它的 Node 引擎或 proot。它能做的，NIBI-GO 都能做——工具面是 App 自己的原生能力，区别只在"谁来调用"。

消费者 ① GO 形态 · 本机 AGENT
随 A+C 落地，不等模块 B。手机内核（libnibi.so）经进程内桥 / abstract socket 调工具面——零网络、App 内部直连。

dsh-Go 用户迁移过来，第一天体验就对齐（且桥少一层 proot 穿透，更简单）。
两条通道
GO：进程内桥（App 内部 · 零网络）
WORK：Relay V2 + phone-bridge 指令面
消费者 ② WORK 形态 · 桌面 Agent
模块 B（最后做）提供的增量：nibi-phone-bridge 把同一工具面经 Relay 暴露给桌面会话——桌面 Agent 操控你的手机，dsh-Go 结构性做不到（它的手机工具只服务本机引擎）。
比喻：工具面是"手"。GO 形态 = 自己的大脑直接指挥自己的手（神经直连，与生俱来）；模块 B = 让别人的大脑也能远程指挥这只手（需要装的通信线路）。手不因通信线路而存在。

5沙箱三层（D13.4 · 内核 SandboxPolicy 的 Android 落地）

第 1 层 · 免费
Android app sandbox + SELinux
引擎进程本就困在 app uid / SELinux 域内，bash 子进程天然继承——可写面 = app 目录 + 授权挂载。默认生效，比桌面裸跑强。
第 2 层 · 强语义
SandboxPolicy 翻译 adapter
内核的平台无关 DTO（filesystem 默认可读不可写 / network / required fail-closed）在 Android 翻译为路径检查 + 权限判决链。required 先设 false 并如实告知——不假装有 bwrap（dsh-Go/DSHA 都只能承认没有）。
第 3 层 · 随 B 顺路
特权 mount namespace
模块 B 的特权通道（Shizuku/ADB shell uid）可 bind-mount 只读化——dsh-Go/DSHA 做不到的事，NIBI-GO 靠 B 反而做得到。

6插件运行依赖：四层供给（按需拉取，不全预装）

第 0 层 · APK 随包（零下载）
bash / busybox / git · Node 24 · Python
覆盖：纯 npm 依赖、纯 pip 包、shell 工具。PNG / Markdown / Word / XLSX / PDF 生成在这里就够了（docx/exceljs/openpyxl/pdfkit 都是纯代码库——Word/XLSX 本质是 zip+XML）。
第 1 层 · 随插件包分发
作者打包 node_modules / wheels
插件包 = 自包含目录，装上即跑（dsh-Go 市场同模式）。适合依赖固定的小插件。
第 2 层 · 运行时按需安装
manifest 声明 dependencies
安装时 npm/pip 装进插件自己的目录（npmmirror/pypi 国内镜像，失败明示原因不静默）。deps 不逃出插件目录（沙箱第 1 层可写面约束），卸载整体删除。
第 3 层 · 桌面兜底（WORK 形态职责）：LibreOffice 级保真互转、重转换——桌面插件做（dsh-Go 同款"Host 转 PDF"），或调云服务的 MCP server。双形态分工又一次兑现：GO 做轻的，重的留给桌面。

付费插件（D16 预留，未启动）：将来开放时 = 市场页加付费分段 + nibi-api 下载链路（Ed25519 license 已是跨语言设计，claims.dev 换手机 deviceId，安全红线照抄桌面 P0 修复）。四层供给不变。

8实施顺序与开工前 Spike

1装 NIBI-GO · 登录 NIBI 账号→ 2扫桌面码（一次 · 配对完成）→ 3切 WORK：遥控桌面（含桌面插件管理）⇄ 4切 GO：手机自主 AGENT + GO 插件市场（离线可用）
Spike 1 · ~1 天
iroh 实测
Node 绑定质量、Android NDK 编译、WiFi↔蜂窝 QUIC 连接迁移。选型中唯一无同行验证的依赖。
Spike 2 · ~1 天
RN 后台长连接
RN WebSocket 后台限制、流式聊天渲染性能。退出保险：relay-client/chat-core 纯 TS 隔离，UI 撞墙可切 Flutter 协议层零返工。
Spike 3 · ~1 天
内核进程内 + W^X
libnibi.so 进程内运行稳定性（panic=abort+看门狗）+ jniLibs spawn 在 targetSdk 36 的合法性（Node 方案唯一技术风险，Termux 高 targetSdk 解法可抄）。

9内核同步策略（D17 · 主线永远不等 GO）

📦 内核的三级消费模式 NIBI-GO 与主线彻底解耦：主线迭代（一晚 31 commits / 14,766 行）对 GO 无强制影响
第 1 级 · 冻结产物消费（默认态）
GO 锁 @nibi-studio/cli-android-arm64@4.0.x（待发布：CI matrix 加一行 + Platform::published() 补一个 entry）。像锁任何 npm 依赖：主线爱怎么迭代怎么迭代，GO 不升级就不受影响。升级时机完全由你定。
↓ 缺东西时
第 2 级 · 票据制
第 2 级 · 票据制（GO 不碰主线）
GO 发现内核缺 android 分支/接口 → 开 issue 票据，你按主线节奏决定做不做、什么时候做。GO 不开分支、不提 PR、不加 review 负担。做完随主线发版，GO bump 版本号即得。
第 3 级 · 分支过渡（仅紧急）：票据来不及、GO 急需时才开分支自改，合并时机由你定；GO 仓先用 git 依赖锁该分支 commit 过渡。

为什么这个模型成立：Phase A（NIBI-WORK）零内核耦合——会话跑在桌面，手机上没有内核代码，主线 kernel 一晚 31 commits 对 A 无任何影响，A 可立即启动；Phase C 需要的稳定面（app-server 入口 / MCP transport / 会话库 0024 账本 / PaidPluginGate）在 4.0.1 已全部现成，主线的高速迭代是行为对齐而非破坏面（今晚 kernel-api +951 行 / -9 行，纯增量）。C 启动的两个信号由你判断：主线 kernel 对齐批次收尾 + android 平台包发布。

今晚 dev 已交付的 GO 相关资产：PaidPluginGate trait（kernel-api，平台无关）+ ext 执行期门禁（工具表冻结防缓存失效）+ 手机远控定位免费（73472fa7）——D16 的内核侧基建已就位。
